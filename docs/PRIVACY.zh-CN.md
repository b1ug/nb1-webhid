# 本地数据与权限

[English](PRIVACY.md) · [安装与移除](DISTRIBUTION.zh-CN.md)

本文描述当前开发候选。更换包后，应重新核对 manifest 与构建身份，再决定设备授权。

## 网页

网页把显式选择的语言保存在当前来源的 localStorage 中。JSON 草稿和编译结果保留在页面内存；导出会下载由你保留的文件，导入文件在本地读取。没有服务器端 Pattern 库，也不会自动连接原生 nb1 的文件库。

随包网页没有分析统计、账号、远程字体、运行时 CDN、PWA service worker 或自动任务监听。本地服务器仅在回环地址提供静态文件。源码和官方文档链接只有在你主动访问时才会跳转到外部资源；浏览器或网络软件自身可能产生独立流量。

关闭网页不会清除浏览器授权，也不等于熄灯。清除站点数据可移除语言选择；撤销后续访问则需在 Chrome 设置中移除该来源的 HID 权限。

## 扩展

manifest 只申请两种权限：

| 权限 | 用途 |
| --- | --- |
| storage | 在扩展本地保留语言选择、一个提醒计划，以及最近状态／错误。 |
| alarms | 触发用户自己创建的分钟级倒计时提醒。 |

提醒记录可以包含截止时间、已解析 RGB、编译请求和后台会话标识。最近事件包含状态、时间与说明，不读取任意网页、浏览历史、系统通知文本、Agent 提示词或原生文件。

数据使用 chrome.storage.local，不使用同步存储或远程服务。设备断开后，最近错误／状态可能保留，直到被新状态替换或扩展数据被移除。卸载时由 Chrome 删除扩展本地数据。导出文件是普通用户文件，不随卸载删除。

扩展没有全站点访问、content scripts、外部消息、native messaging、downloads、tabs、键盘、录屏、辅助功能或系统通知权限，也不会自动观察任务完成。

## 设备授权

WebHID 通过显式操作触发独立的浏览器设备选择器，只过滤 blink(1) 的厂商 **0x27b8**、产品 **0x01ed**。这不是读取键盘输入的请求。

即使网页或扩展已经获得授权，其他控制器仍可能占用灯，导致打开失败。勾选占用确认不能替你停止另一个进程，应显式交接控制权，不要用无关系统权限绕过问题。

当前只提供受限灯光指令，不开放 Pattern 行、Flash、上电效果或任意 HID 报文写入。Disconnect 与 Off 不同：已经被接受的颜色，可能在网页或扩展退出后继续保持。

浏览器授权模型见 [Chrome WebHID 扩展指南](https://developer.chrome.com/docs/extensions/how-to/web-platform/webhid)。反馈问题时使用仓库已有问题渠道，提供浏览器／OS／构建身份和脱敏错误，除非必要，不附带私人草稿或无关设备信息。
